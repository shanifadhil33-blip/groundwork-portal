# Order number visibility

Order numbers are identifiers. The dashboard's Today and Needs action lists and Waiting prices used split children (`WO ` and a numeric child) without `data-no-translate`. `Translated` therefore treated the prefix as interface copy. With a pending dictionary, server HTML contained a hidden, busy ellipsis followed by the number. These React-owned wrappers are deliberately excluded from the DOM translator. The earlier t14d fix is retained.

All `.order-number` spans now carry `data-no-translate`, consistently with the existing work-order card. This covers dashboard, price review, client home, work-order list and detail. The prefix and number render verbatim even before a dictionary is ready; other interface copy retains its translation/loading behavior.

Browser investigation: starting the existing on-disk production build in a new process did **not** reproduce the historical persistent placeholders, before these additional changes. All ten previously affected persona/language combinations were inspected at mobile dimensions. For example, Sam/Hindi returned `<span class="order-number"><span data-no-translate="" data-translated-copy="">WO </span>1</span>` in server HTML and the hydrated DOM. Its host fiber also had `children: "WO "`, no hidden style and no busy attribute; its translation context had `language: "hi"` and a non-null dictionary. The corresponding Arabic and other affected accounts were also visible. Thus missing context, a null dictionary at inspection time, and retained hidden hydration attributes were not observed in this fresh process. A stale prior server process/build is plausible (the earlier report records an occupied port), but cannot be established from the historical JSON alone. This change fixes the independently reproduced identifier/loading defect; it does not claim a proven diagnosis of the unavailable historical browser state.

Regression coverage uses the actual Needs action and Waiting prices components, with split string/number children, in Hindi, Arabic and English. It checks server HTML before hydration and DOM after hydration, both with loaded and pending dictionaries. Before the identifier change, the two non-English cases failed with `…39` instead of `WO 39`; afterward they pass. Pending dictionary interface headings remain busy, so the assertion also protects against revealing English interface copy.
